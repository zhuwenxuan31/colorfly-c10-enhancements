# 构建与回退

## 主机测试

在仓库根目录运行 `sh tools/check-host.sh`。该入口只使用本地测试夹具，临时文件由脚本清理。

## 固件研究与构建

原厂 C10 使用小端 MIPS32 O32 和 Linux 2.6.31.3。各目录中的 `build.*` 和 `prepare_package.py` 记录了原始构建步骤。完整固件构建依赖本地原厂组件和逐版输入，当前仓库提供可直接运行的主机测试与源码级归档。

- 自行准备与硬件匹配的原厂升级包，解包得到既有构建脚本要求的 `kernel.raw`、应用目录与模块。构建所用的原厂组件和上一版本输入须匹配脚本中的 SHA-256。
- 先配置 MIPS32LE O32 交叉编译器、Python 的 pyelftools／Unicorn、e2fsprogs 的 debugfs／e2fsck，以及相应构建脚本中引用的本地路径。
- 构建脉络为 v58 睡眠定时 → v60 双定时 → v70 实时 EQ → v72 USB DAC → v74 同步歌词 → v80 目录删除。v84、v86 是基于 v80 的独立 DAC 实验。历史中间构建产物需在本地准备。
- 打包器把应用分区作为唯一升级目标。检查应用镜像文件清单、非应用载荷的字节一致性、容器 CRC 和升级分区选择后，再进行实机测试。

## 实机回退

升级前保留已知正常的同型号应用镜像，并保留原厂升级工具。回退包使用原厂扫描入口，版本号可高于当前试验包，应用载荷恢复到对应稳定基线。每次回退后实测开机、本地播放和当前使用的 USB DAC。通过菜单回退的记录仅覆盖仍能进入原厂升级入口的设备。
